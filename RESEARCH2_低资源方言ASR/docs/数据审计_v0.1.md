# RESEARCH2 数据审计 v0.1

日期：2026-09-20

## 结论

当前优先使用本地四川话数据做第一阶段 ASR / 方言适配实验；暂不把它当作“双目标规范化”数据集。

原因是本地数据只有一列 `TRANSCRIPTION`，没有同一音频对应的第二套规范文本。它可以支持零样本 ASR、监督微调、单 LoRA 和按地区/说话人错误分析，但不能直接证明“方言原文输出”和“规范文本输出”两个适配器的效果差异。

吴语 `WenetSpeech-Wu-Bench` 的 AST 文件有 3,000 条音频和普通话目标文本，ASR 文件有 4,851 条音频和吴语转写；原始 `utt_id` 字符串交集为 0，但 AST id 去掉 `_seg00` 等切片后缀后可映射到 2,363 个 ASR 父样本。严格保守地只保留“单个 AST 切片 + 音频时长比父 ASR 音频至少 0.95”的样本，可得到 403 条候选双文本样本。

这 403 条样本可以做小规模双输出方法 pilot，但不能直接当作完整配对语料：多段 AST 父样本被排除，且 parquet 中没有说话人字段，所以当前 split 只能做到父 utterance 隔离，不能证明说话人隔离。完整的 WenetSpeech-Wu-Bench 仍适合作为吴语 ASR 与吴语到普通话 AST 的两个独立外部任务。

## 已跑通的第一版基线

### Whisper tiny 监督基线

- 训练集：9,420 条，22 个说话人；dev：1,076 条，6 个说话人；test：2,572 条，10 个未见说话人。
- 训练：`openai/whisper-tiny`，1 epoch，batch size 4，learning rate `1e-5`。
- 训练耗时：约 33.6 分钟。
- train loss：`0.8021`；dev loss：`0.9974`。
- test 解码：`max_new_tokens=64`、`no_repeat_ngram_size=3`、`repetition_penalty=1.05`。
- test mean utterance CER：`0.7341`（2,572 条）。

地区 CER：泸州 `0.4860`、达州 `0.6005`、重庆 `0.6818`、成都 `0.6826`、宜宾 `0.7050`、广安 `0.7079`、自贡 `0.6942`、乐山 `0.7579`、内江 `0.8740`、雅安 `1.6475`。雅安测试集只有一个说话人，需在后续检查说话人/文本分布后再解释该异常值。

结果文件：

- `results/whisper_tiny_full_epoch1/summary.json`
- `results/whisper_tiny_full_epoch1/eval_test_full.json`
- `results/whisper_tiny_full_epoch1/eval_test_full.jsonl`
- `results/whisper_tiny_full_epoch1/checkpoint_epoch_1/`

说明：此前 dev 解码出现超过 1 的 CER，主要受生成末尾重复标点和短语影响；加入重复抑制后，dev64 CER 为 `0.6787`。正式 test 数字采用同一套受控解码参数。

### 3 epoch 对照

- 3 epoch train loss：`0.8021 → 0.4877 → 0.3429`。
- dev loss：`0.9975 → 0.9374 → 0.9404`，第 2 epoch 最低。
- test mean CER：`0.8297`，高于 1 epoch 的 `0.7341`；因此当前不把“训练更久”视为改进，后续应以 held-out test 和 early stopping 为准。
- 3 epoch 结果文件：`results/whisper_tiny_full_epoch3/summary.json`、`eval_test_full.json`。

### LoRA 对照

LoRA 的 PEFT/Whisper 兼容性已通过 8 条 smoke 验证，训练参数约 14.7 万，占 tiny 总参数 `0.389%`。自动队列正在运行全量 LoRA 对照；如果某一项失败，控制器会停止而不会盲目重试。

## 四川话外部资源：WenetSpeech-Chuan

本轮重新核验了官方主页、仓库和 Hugging Face 文件结构：WenetSpeech-Chuan 官方资料称约 10,000 小时川渝方言语音，metadata 包含 speaker identity、地区、年龄、性别、音频质量和时间戳；WSC-Eval-ASR 公开 Easy 8.55 小时、Hard 1.15 小时的人工核验 ASR benchmark。官方训练 README 的核心字段仍是单一 `text`/`rover_result` 转写，未发现同一音频对应的普通话规范文本字段；训练元数据约 1.43 GB，预处理音频还需按官方说明联系获取。因此它适合补充 speaker-aware 四川话 ASR 外部评测，不会自动解决双文本规范化标签缺口。

已完成一个低成本接入 smoke：从 WSC-Eval-ASR Easy 下载 8 条样本（约 1.05 MB），缓存 Whisper-tiny zero-shot 平均 CER `0.7232`；本地四川话 3 epoch LoRA 在同一 8 条上的 CER 为 `0.5696`，逐样本 bootstrap 改善 `0.1535`，但样本太小不能宣称外部泛化。该结果用于脚本/数据接入验证，不是正式 benchmark；详见 `WenetSpeech-Chuan_smoke_report_v0.1.md`。

## 吴语备选数据

官方资源：

- WenetSpeech-Wu 仓库：<https://github.com/ASLP-lab/WenetSpeech-Wu-Repo>

已下载并检查：

- `understanding/ast.parquet`：3,000 条，字段为 `task / utt_id / audio / label`
- `understanding/asr.parquet`：4,851 条，字段为 `task / utt_id / audio / label`
- 两个文件的 `utt_id` 交集：0
- 去除 AST 切片后缀后可映射 ASR 父样本：2,363 个
- 保守双文本 pilot：403 条，划分为 train 278 / dev 57 / test 68
- pilot 生成脚本：`scripts/build_wu_paired_manifest.py`
- pilot 输出：`data_wu_paired_pilot/`
- Hugging Face 数据集许可证字段：Apache-2.0
- pilot v0.1 结果：`wu_paired_pilot_report_v0.1.md`

因此暂定：

1. 四川话用于第一阶段方言 ASR 主实验；
2. 吴语用于外部 ASR / AST 对照，不直接作为双 LoRA 配对训练集；
3. 先使用 403 条吴语候选做双输出方法可行性 pilot，但明确标注其无说话人隔离限制；
4. 四川话仍用于主实验，若论文主问题最终确定为“双输出规范化”，再人工补标四川话小规模双文本子集；
5. 若后续获得带同一音频、同一说话人划分的 WenetSpeech-Wu 完整双文本标注，再增加正式规范化实验。

已为四川话主线生成 `sichuan_norm_annotation_template/sichuan_norm_annotation_500.jsonl`：500 条 train 样本，覆盖 12 个地区、22 个训练说话人，`norm_text` 全为空并要求人工填写；抽样不含四川话 dev/test 说话人，500 个音频路径均已验证存在。标注说明见同目录 `README.md`。
结构检查结果保存在 `sichuan_norm_annotation_template/validation.json`：`valid_structure=true`，但 `ready_for_training=false`，因为当前仍有 500 条空的 `norm_text`。

为降低人工起标成本，新增了本地 Ollama 候选生成器 `scripts/generate_norm_candidates_ollama.py`。它只生成单独的 `norm_text_candidate` 字段，不修改正式 `norm_text`/`norm_status`，因此不会绕过人工标注 gate。中文提示版本在 100 条 smoke 中成功解析 99 条，其中 62 条发生改写、37 条保持原文、1 条因 JSON 截断失败；v1 曾出现英文输出，已废弃。候选结果与边界记录见 `四川话规范化候选生成_smoke_report_v0.1.md`。当前正式数据仍不可训练。

已进一步生成 `sichuan_norm_annotation_template/norm_review_queue_500.jsonl`：500 条候选按模型错误、英文、阿拉伯数字变化、长度异常和大幅改写分级；当前高/中/低优先级分别为 12/312/176。该队列的 `human_norm_text` 仍为空，仅供人工审核，不能直接作为训练 manifest。

新增 `scripts/finalize_sichuan_norm_annotations.py` 作为安全落盘器：只有审核队列显式标记 `accepted/edited` 才会写入新的正式标注文件；`--require-complete` 会拒绝任何未审核行，并且不会覆盖原模板。当前用全空队列回归验证，退出码为 1、正式输出文件未创建，说明 gate 生效。

为方便队友审核，新增 `scripts/review_norm_tsv.py`，已将 500 条队列导出为 `sichuan_norm_annotation_template/norm_review_sheet_500.tsv`，并完成一次 500 行 round-trip 导入验证；当前仍是 `unreviewed=500`，没有任何文本被自动写回。

新增 `scripts/validate_research2_state.py` 做统一状态审计：当前 train/dev/test 说话人交集均为空，标注模板与四川话 test 说话人也无交集；普通结构审计通过，但 `--require-paired` 正确返回失败，因为 500 条 `norm_text` 仍为空。这一状态写入 `results/research2_state_audit.json` 与 `results/research2_state_audit_require_paired.json`。

预飞检查还发现并修复了 paired manifest 的 split 缺口：500 条模板原本全部标为 train，task-control 训练需要 dev；`build_paired_manifest_from_annotations.py` 现支持 `--dev-speakers`，按完整说话人划分 dev，避免 train/dev 说话人泄漏。当前空模板 dry-run 仍安全失败，未生成 manifest。

同时统一修复了多个 JSONL 脚本对 `splitlines()` 的使用，改为按真实换行读取，避免文本中出现 Unicode 行分隔符时破坏 JSONL；涉及 paired builder、模板校验、训练读取、task-control 输出分析和错误分析脚本。

新增 `scripts/test_research2_pipeline.py` 做正向端到端回归：临时构造 4 条已审核 fixture，成功跑通 finalizer → `--dev-speakers` paired builder，并验证 train/dev 说话人不交叉、训练字段完整；fixture 不写入正式数据，也不使用 GPU。

finalizer 进一步增加不可变字段校验：审核队列中的 `dialect_text`、`audio_path`、`speaker_id`、`region` 必须与原始模板逐行一致；当前 500 条空队列仍以退出码 1 拒绝，未生成正式文件。

审核工具现支持分批处理：可先导出 12 条 `high` 风险样本，使用 `--allow-partial` 导回并保留其余 488 条状态；这只降低人工起步成本，不降低最终 `--require-complete` 训练 gate。partial round-trip 已验证 500 行队列保持完整。

初步 pilot 已完成：在 68 条相同测试样本上，使用扩展训练集后的独立方言/规范 LoRA CER 为 `0.8245` / `0.8493`；共享 task-control LoRA CER 为 `0.8186` / `0.8445`，相对 tiny zero-shot 的方言 `0.9080` / 普通话 `0.9109` 分别改善 `0.0894` / `0.0664`。两个 LoRA 更新直接相加后 CER 分别升至 `1.0799` / `1.0827`，说明简单叠加会产生明显干扰。task-control 相对独立 LoRA 的 paired bootstrap 95% CI 分别为 `[-0.0206, 0.0319]` 与 `[-0.0156, 0.0251]`，暂不能声称显著优于独立方案。该结果只作为方向性证据，不能替代 speaker-disjoint 的正式实验。详见 `wu_paired_pilot_report_v0.3.md`。
